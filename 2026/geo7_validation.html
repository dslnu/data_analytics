Validating spatial predictions

A supplement to Geo 7

Not part of the book

Geo 7 follows Part III of Geographic Data Science with Python. Those chapters fit spatial models and interpret their coefficients, but they never evaluate out-of-sample prediction — there is no cross-validation anywhere in them.

This supplement adds that missing step. It reuses Geo 7’s San Diego Airbnb data and baseline regression, and asks whether the accuracy such models report is as good as it looks.

Where Geo 7 left off

The baseline model and its residuals

import spreg
from libpysal import weights

db = geopandas.read_file(f"{GDS}/airbnb/regression_db.geojson")
variable_names = [
    "accommodates", "bathrooms", "bedrooms", "beds",
    "rt_Private_room", "rt_Shared_room",
    "pg_Condominium", "pg_House", "pg_Other", "pg_Townhouse",
]
m1 = spreg.OLS(
    db[["log_price"]].values, db[variable_names].values,
    name_y="log_price", name_x=variable_names,
)
knn = weights.KNN.from_dataframe(db, k=20)
knn.transform = "R"
lag_u = weights.spatial_lag.lag_spatial(knn, m1.u)

print(f"R2 (in-sample)                 = {m1.r2:.4f}")
print(f"corr(residual, neighbours' lag) = {numpy.corrcoef(m1.u.flatten(), lag_u.flatten())[0, 1]:.4f}")
R2 (in-sample)                 = 0.6683
corr(residual, neighbours' lag) = 0.3348

The same model as in Geo 7: two-thirds of the variation in log price, and errors that cluster in space.

The question nobody asked

Everything so far was in-sample

Every \(R^2\) in Geo 7 describes how well a model fits the data it was fitted on. For explanation that is defensible. For prediction it is not, and prediction is what you will usually be asked for.

The standard answer is cross-validation: hold out a fold, fit on the rest, score on the held-out part, repeat.

We are about to see that the standard answer does not work on spatial data, for a reason Geo 7 already established.

Recall the diagnostic

We measured this in Geo 7

The regression’s residuals are spatially autocorrelated — correlation 0.33 with their 20-neighbour spatial lag, computed above. Nearby listings have similar prices and similar errors.

Now consider what random \(k\)-fold cross-validation does with that. It shuffles rows and cuts them into five parts. Every test listing has, almost certainly, several of its immediate neighbours in the training set.

So the model is not predicting an unseen location. It is interpolating between points it has already seen — and interpolation is easy.

This is leakage

The same failure as Bio 2, in different clothing

not independent random CV therefore
taxonomy strains within a genus tests on near-duplicates of training sequences
single cell cells within a donor treats one donor as thousands of replicates
geography nearby places tests on the interior of the training set

The rule is the same in all three: split at the level you want to generalise to. If you want to predict prices in a district you have no data for, your folds must be districts.

Setting up an honest test

Features, target, and a projected CRS

from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import cross_val_score, KFold, GroupKFold

dbm = db.to_crs(epsg=3857)          # metres, so blocks are metres
xy = numpy.column_stack((dbm.geometry.x, dbm.geometry.y))
y = dbm["log_price"].values

house = ["accommodates", "bathrooms", "bedrooms", "beds"]


def rf():
    return RandomForestRegressor(n_estimators=120, random_state=0, n_jobs=-1)


def blocks(size):
    """Assign each listing to a square block of `size` metres."""
    bx = ((xy[:, 0] - xy[:, 0].min()) // size).astype(int)
    by = ((xy[:, 1] - xy[:, 1].min()) // size).astype(int)
    return bx * 10_000 + by

Reproject first. Blocks must be defined in metres; dividing degrees by 4000 is meaningless.

Isolating the leak

Three models, two validation schemes

g = blocks(4000)
rows = []
for name, X in [
    ("coordinates only", xy),
    ("house features only", dbm[house].values),
    ("features + coordinates", numpy.column_stack([dbm[house].values, xy])),
]:
    r = cross_val_score(rf(), X, y, cv=KFold(5, shuffle=True, random_state=0),
                        scoring="r2").mean()
    b = cross_val_score(rf(), X, y, cv=GroupKFold(5), groups=g, scoring="r2").mean()
    rows.append((name, r, b, r - b))

print(f"{'model':<26}{'random':>9}{'block':>9}{'drop':>8}")
for n, r, b, d in rows:
    print(f"{n:<26}{r:>9.3f}{b:>9.3f}{d:>8.3f}")
model                        random    block    drop
coordinates only              0.166   -0.103   0.270
house features only           0.607    0.583   0.024
features + coordinates        0.653    0.602   0.050

Read that table again

The coordinates-only model is the proof

Under random CV a model using nothing but latitude and longitude scores \(R^2 \approx 0.17\). It looks like it learned something about San Diego.

Under block CV the same model scores negative — worse than predicting the mean price for every listing.

All of its apparent skill was memorising neighbours. Remove the neighbours from the training set and there is nothing left, because there was never anything there.

And the contrast

house features only barely moves between the two schemes. Bedrooms and bathrooms are not spatial, so blocking costs nothing. The gap belongs to the coordinates, and only to them.

How big are the blocks?

Sweep the block size

Code 
X = numpy.column_stack([dbm[house].values, xy])
rand = cross_val_score(rf(), X, y, cv=KFold(5, shuffle=True, random_state=0),
                       scoring="r2").mean()

sizes, scores = [], []
for s in (250, 500, 1000, 2000, 4000, 8000):
    gg = blocks(s)
    if len(numpy.unique(gg)) < 5:
        continue
    sizes.append(s)
    scores.append(cross_val_score(rf(), X, y, cv=GroupKFold(5), groups=gg,
                                  scoring="r2").mean())

for s, sc in zip(sizes, scores):
    print(f"  block {s:>5} m : R2 = {sc:.3f}")
print(f"  random CV      : R2 = {rand:.3f}")

f, ax = plt.subplots(figsize=(5, 3))
ax.semilogx(sizes, scores, "o-", label="block CV")
ax.axhline(rand, ls="--", color="grey", label="random CV")
ax.set_xlabel("block size (m)"); ax.set_ylabel("$R^2$"); ax.legend()
plt.tight_layout(); plt.show()

Reading the curve

What this curve actually shows

Read the numbers, not the story you expected.

At 250 m the block score equals random CV (0.656 vs 0.653). Blocks that small barely separate anything — a 250 m block still leaves neighbours in the training set. That agreement is a useful sanity check: it confirms the mechanism is distance, not the GroupKFold machinery.

The trend is downward but not monotone. 1 000 m scores below 2 000 m here. With five folds over a few hundred blocks, each estimate carries real variance, and a single sweep is noisy. Repeat with several random block origins before reading much into any one point.

It has not flattened by 8 km. San Diego spans roughly 40 km, so even 8 km blocks leave training listings fairly close to test ones. The honest conclusion is that we have not yet reached the distance at which leakage stops.

So what do you report?

Not a plateau, because we do not have one. Report the score at the block size matching your intended use: if you will predict 5 km from your nearest training data, the 4–8 km numbers are the relevant ones — around 0.57–0.60, against the 0.65 that random CV advertises.

The optimism here is modest precisely because most of this model’s signal is non-spatial. That is the reassuring case. The coordinates-only model a few slides back is the other one.

Buffered leave-one-out

A stricter variant

Blocks still put some test points right next to a block boundary, and so next to training data. Buffered LOO removes that: hold out one observation, and also delete from the training set everything within radius \(r\) of it.

for i in range(n):
    d = distances_from(i)
    train = (d > buffer_radius)
    model.fit(X[train], y[train])
    pred[i] = model.predict(X[[i]])

Expensive — one fit per observation — but it gives a clean answer to “how well do I predict at distance \(r\) from any data?”, which is often the actual question.

Checking the residuals again

Close the loop

The residual diagnostic from Geo 7 is also the one that closes this lecture. After fitting any predictive model, compute Moran’s I on its residuals.

  • Significant autocorrelation remaining → there is spatial structure the model has not captured. Consider the spatial regression models and the engineered features from Geo 7.
  • No autocorrelation → the spatial structure is accounted for, and the i.i.d. assumption behind your inference is defensible.

It costs three lines and it is the single most informative check you can run on a spatial model.

The thread

One lesson, three courses

Geo 5 and 6 taught you to measure spatial dependence. Geo 7 used it to improve models; this supplement used it to distrust them.

The second use is the transferable one. Spatial autocorrelation is a specific case of the general problem that observations are not independent — the same problem as related organisms in Bio 2 and cells from one donor in Bio 4.

Before trusting a score, ask what the unit of independence actually is.

Questions: spatial regression

From the book

  1. The “Spatial Durbin Model” combines the SLX model with the spatial lag model; the “Spatial Durbin Error Model” combines SLX with the spatial error model. Fit a Spatial Durbin variant of the models in this lecture.
    • Do these variants improve the model fit?
    • What happens to the spatial autocorrelation parameters (\(\rho\), \(\lambda\)) when the SLX term is added? Why might this occur?
  2. Spatial error models recover the same estimates (asymptotically) as OLS, but their confidence intervals change, because OLS miscalculates them under spatial correlation and/or heteroskedasticity. How much do the confidence intervals change when the spatial error model is fit?
  3. A common justification for the SLX model (and the Durbin variants) is omitted, spatially patterned variables: if an omitted variable is associated with the included variables and is spatially patterned, the spatial structure of the included variables can mimic it. In the spatial lag model:
    • what variables might be missing that matter for predicting the price of an Airbnb?
    • would they have a spatial pattern similar to the included variables? Why or why not?
  4. Spatial regression focuses on how nearby observations are similar; platial models — multi-level or spatial mixed-effect models — focus on how observations in the same spatial group are similar. When do these two ideas work well together, and when might they disagree?
