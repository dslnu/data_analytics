Big Data Analytics: Lab on file formats

File formats

Exercises for the first part of the Storage formats lecture: encodings, Parquet, Arrow. Answer each exercise in a notebook, with the output that supports your answer.

Setup

uv venv -p 3.12 .venv-formats && source .venv-formats/bin/activate
uv pip install duckdb pyarrow polars pandas msgpack fastavro jupyter

Data for Parts 2–5: 1M synthetic taxi trips (customer_id takes only even values).

import duckdb
con = duckdb.connect()
con.sql("""
SELECT setseed(0.42);
CREATE TABLE trips AS
SELECT i                                                   AS trip_id,
       TIMESTAMP '2025-01-01' + to_seconds(i * 10)         AS pickup_ts,
       (i // 100000)::INTEGER                              AS vendor_id,
       ['cash', 'card', 'app'][1 + (hash(i) % 3)::INTEGER] AS payment,
       1000 + (random() * 50)::INTEGER                     AS zone_id,
       round(random() * 100, 2)                            AS fare,
       2 * (random() * 20000)::INTEGER                     AS customer_id
FROM range(1000000) t(i);
""")

Part 1: Encoding one record

Use the record from the lecture: {"userName": "Martin", "favoriteNumber": 1337, "interests": ["daydreaming", "hacking"]}.

  1. Encode it as compact JSON and with msgpack.packb. Compare the sizes (81 and 66 bytes) and, in the hex dump, mark the map header, the field names and the number 1337. MessagePack spec
  2. Write a Protobuf encoder by hand (varints, keys tag << 3 | wire_type) for the lecture’s Person schema and get the 33 bytes. Decode b9 0a to 1337 on paper. How many bytes does -1 take as int64, and what do sint64 and ZigZag fix? Protobuf encoding
  3. Write a decoder that knows only tags 1–3 and skips unknown fields. Append a field with tag 4 and decode. Why can the old decoder skip it? What breaks if tag 2 is reused for a string? Updating a message type
  4. Encode the record with Avro (fastavro.schemaless_writer) and get 32 bytes. Explain the bytes 02 f2 14. Avro specification, fastavro
  5. Read the Avro bytes with a different reader’s schema: (a) userName renamed via aliases and a new field with a default, (b) a new field without a default, (c) the reader’s schema passed as if it were the writer’s. Explain each result. Where is the writer’s schema stored in an Avro file? Schema resolution

Part 2: Text files vs Parquet

  1. Write trips as CSV, JSON, and Parquet uncompressed / Snappy / zstd (COPY trips TO 'f.parquet' (FORMAT parquet, COMPRESSION zstd)). Compare the sizes. Where does uncompressed Parquet save space? DuckDB: Parquet export
  2. Time SELECT avg(fare) and SELECT * on the CSV and the Parquet file (run each twice). Explain why one column is cheap only for Parquet.

Part 3: Inside a Parquet file

Use DuckDB’s parquet_schema, parquet_metadata and parquet_bloom_probe. DuckDB: Parquet metadata, Parquet file format

  1. How many row groups does the zstd file have, and how many rows each? Compare stats_min/stats_max of trip_id and zone_id across row groups: for which column are these zone maps useful? Why is the footer at the end of the file?
  2. Per column, sum total_compressed_size and list encodings. Which columns are dictionary-encoded, and why does trip_id take megabytes although it is just 0, 1, 2, …?
  3. Write the file again with PARQUET_VERSION v2. Which encodings change, and how small do trip_id and pickup_ts get? Why can zstd not find this pattern on its own? Parquet encodings
  4. Write a copy sorted by random(). With EXPLAIN ANALYZE SELECT count(*) FROM ... WHERE trip_id BETWEEN 500000 AND 500100, compare “Row Groups Scanned” and “Data Read” for both files. Repeat with zone_id = 1007 and zone_id = 1077. DuckDB: profiling
  5. Write a copy with ROW_GROUP_SIZE 10000. What does the query from 11 read now, and what does it cost?
  6. Which columns got Bloom filters (bloom_filter_offset in parquet_metadata)? Probe customer_id for 778 and 777, and compare EXPLAIN ANALYZE for both. Why does min/max not help for 777 but the Bloom filter does? Why does it not help for customer_id > 777? Parquet Bloom filter

Part 5: Apache Arrow

Arrow columnar format

  1. Print the buffers (arr.buffers()) of pa.array(["Lviv", None, "Kyiv"]), of pa.array([10, None, 30]) and of pa.array([1, 2, 3]). What is in the slot of a null, and where is the validity bitmap of the last array?
  2. Compare pd.Series([10, None, 30]) with the same series as pd.ArrowDtype(pa.int64()), and run pc.is_nan on [1.0, NaN, None]. What does the validity bitmap give you? pandas: PyArrow functionality
  3. Slice a 1M-element array: does it copy? Print the buffers of a pa.string_view() array with short and long strings, and explain their sizes.
  4. Write trips as Arrow IPC and as Parquet. Compare sizes on disk, and the memory allocated (pa.total_allocated_bytes()) and time when reading the IPC file memory-mapped, the IPC file normally, and the Parquet file. When would you use each? pyarrow: IPC and memory mapping
  5. Pass the memory-mapped table to Polars (pl.from_arrow), query that DataFrame from DuckDB, and convert it to pandas with Arrow dtypes. Which steps copied data? Check by comparing buffer addresses. DuckDB: SQL on Arrow
