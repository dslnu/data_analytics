Big Data Analytics: Lab on file formats

File formats on real data

Two analytics problems where the data is too big, too messy or too remote to just pd.read_csv it. Work in a Jupyter notebook. For each step, keep the code, the output, and a sentence or two answering the questions.

uv venv -p 3.12 .venv-formats && source .venv-formats/bin/activate
uv pip install duckdb pyarrow polars pandas matplotlib jupyter

Docs you will need: DuckDB Parquet, Parquet metadata, EXPLAIN ANALYZE, Arrow columnar format, Polars user guide, pandas with PyArrow.

Problem 1: Did NYC congestion pricing change taxi traffic?

On 5 January 2025, New York started charging vehicles entering Manhattan south of 60th Street (the Congestion Relief Zone). Did yellow taxi trips into the zone change, and did traffic in the zone get faster? Compare January–March 2025 with January–March 2024.

Data: NYC TLC trip records (column descriptions): one Parquet file per month, ~3–4M trips each. Download December–March of both winters (8 files, ~470 MB) and the zone lookup table:

for ym in 2023-12 2024-01 2024-02 2024-03 2024-12 2025-01 2025-02 2025-03; do
  curl -O https://d37ci6vzurychx.cloudfront.net/trip-data/yellow_tripdata_$ym.parquet
done
curl -O https://d37ci6vzurychx.cloudfront.net/misc/taxi_zone_lookup.csv

1.1 Look before you load

  • Load one month with pd.read_parquet. How much memory does it take (df.memory_usage(deep=True)), compared to the file size? How much would all 8 months take?
  • With DuckDB, inspect the files without reading the data: parquet_file_metadata, parquet_schema, parquet_metadata. Who wrote them? How many row groups, and how many rows per row group? Do the columns have statistics (stats_min, stats_max)?

1.2 Schema drift

  • Compare DESCRIBE of the 2023-12, 2024-01 and 2025-01 files. Which column names, types and columns differ?
  • Run SELECT * FROM 'yellow_tripdata_*.parquet' LIMIT 1 and then the same with read_parquet(..., union_by_name = true). Which column does the first query silently lose? Combining schemas

1.3 Build a clean dataset

Write one clean, typed dataset: consistent snake_case names and integer types, cbd_congestion_fee as 0 before 2025, only trips with a pickup between 2023-12-01 and 2025-03-31 and with dropoff after pickup. Partition it by year and month (Hive-style year=.../month=.../), sort by pickup time, use zstd and PARQUET_VERSION v2. Partitioned writes, Hive partitioning

  • How many trips did you drop, and why? Which pickup dates outside the range did you find in the raw files?
  • Compare the total size, and the encodings of the two timestamp columns, with the raw files.
  • Check stats_min/stats_max of pickup_ts per row group in one of your files. Is the data really sorted? If you used COPY ... PARTITION_BY it probably is not: why? Fix it (for example: one COPY ... ORDER BY per month).

1.4 Measure what the rewrite bought

For “trips on 15 January 2025”, compare EXPLAIN ANALYZE on the raw files and on your dataset: files read, row groups scanned, data read, time. Then add WHERE year = 2025 AND month = 1. Explain each difference using the lecture: statistics (zone maps), sort order, partition pruning.

1.5 Find the zone from the data

The trip records do not say which zones are inside the Congestion Relief Zone, but 2025 trips carry cbd_congestion_fee.

  • Which values does cbd_congestion_fee take?
  • For each dropoff zone (join taxi_zone_lookup.csv), compute the share of 2025 trips that paid the fee. Which zones have a share above ~85%? Do they match “Manhattan south of 60th Street”? Why are some zones around 50%, and why do the airports show up?

1.6 The analysis

For January–March 2024 vs 2025, compute with DuckDB on your clean dataset:

  • trips per week, into the zone and in total
  • median speed (mph) of trips that start and end in the zone (filter out unrealistic distances and durations)
  • average fare, tip and total amount

Hand the weekly result to Polars or pandas without copying (.pl(), .arrow()), and plot 2024 vs 2025 by week of the year. Answer the question in a short paragraph. What else could explain the difference (weather, holidays, ride-hailing apps whose data is in the separate FHV files)?

1.7 Arrow in between

  • Read one cleaned month with pyarrow.parquet.read_table and write it as an Arrow IPC file. Compare file size, and the time and memory (pa.total_allocated_bytes()) of reading it memory-mapped (pa.memory_map) vs reading the Parquet file. IPC and memory mapping
  • Which columns contain nulls, and are they null in the same rows? Print the buffers of one chunk of passenger_count and explain their sizes.

Problem 2: What is in a Ukrainian web corpus?

Large language models are trained on web text. FineWeb-2 (paper) is an open corpus built from Common Crawl, in Parquet on Hugging Face. Its Ukrainian part (ukr_Cyrl) is 91 GB in 20 files. Which sites does the text come from, from which years, how much was duplicated, and how do the topics change over time?

2.1 Query without downloading

DuckDB reads hf:// paths directly (DuckDB on Hugging Face):

f = "hf://datasets/HuggingFaceFW/fineweb-2/data/ukr_Cyrl/train/000_00000.parquet"
  • Read the schema and parquet_file_metadata of this 4.8 GB file. How long does it take, and how much is downloaded?
  • With parquet_metadata, compute the compressed size per column. Which share of the file is text?
  • Count documents per dump with EXPLAIN ANALYZE. How much data is read, and how long does it take? How many row groups does the file have, and how many rows each? Explain why reading a few MB takes so long over HTTP, and what row group size you would choose for files that are read remotely.

2.2 Work locally

Download the test split (71 MB, ~40,000 documents):

curl -L -o fineweb2_ukr_test.parquet \
  https://huggingface.co/datasets/HuggingFaceFW/fineweb-2/resolve/main/data/ukr_Cyrl/test/000_00000.parquet

With DuckDB:

  • documents per crawl year (from dump, e.g. CC-MAIN-2023-14)
  • the 20 most common websites (extract the host from url)
  • the distribution of minhash_cluster_size: what does it mean (see the dataset card), and which share of documents had near-duplicates?
  • document length quantiles, and language_score; look at a few documents with the lowest score

2.3 Text in Arrow, pandas and Polars

  • Read the file with pyarrow.parquet.read_table. Compare the size in memory with the file size. Which Arrow type does text have, and what are its buffers?
  • Convert to pandas: what dtype does text get, and how long does the conversion take? Compare with a column of Python str objects (to_pylist()).
  • Count documents mentioning Lviv ((?i)львів) with a Python loop and with Polars (string expressions). Why is Polars faster?

2.4 Topics over time

With Polars, compute per crawl year: the number of documents, and the share mentioning the war ((?i)\bвійн) and COVID ((?i)коронавірус|covid). Plot it. What happens in 2020 and 2022? Why is this a biased measure (what does Common Crawl collect, and what did FineWeb-2 filter out)?

Optional: Vortex

With DuckDB’s Vortex extension (INSTALL vortex; LOAD vortex;, then COPY ... (FORMAT vortex); docs, DuckDB extension):

  • Write one cleaned taxi month as Vortex. Compare size and the query times from 1.4 and 1.6 with Parquet.
  • Write the FineWeb-2 test split as Vortex: once only the text column, once all other columns. Compare sizes with Parquet + zstd. On which kind of data does Vortex’s choice of lightweight encodings pay off, and on which does it not?
