1. GC content with Dask — and where parallelism pays off

1a. GC content of the whole database

Note

A bag uses processes by default. In a notebook that just works; in a .py script, put the compute() call under if __name__ == '__main__':, or worker start-up fails with a RuntimeError.

The lecture’s searches spend almost all their time in alignments. Each query is independent of the others, so the search is embarrassingly parallel across queries.

  • Check that the parallel results equal the serial ones.
  • Why does scheduler='threads' give no speedup here? (Hint: the GIL.)

2c. An inverted index

Even with sets, each query is still compared with every reference. Turn the problem around: build a dictionary from each k-mer to the references that contain it. For a query, look up its k-mers and count how often each reference appears: that count is the number of shared k-mers. References that share nothing are never touched. This lookup is the seeding step in BLAST.

4. Real reads from a mouse gut

So far the queries were cut out of the reference database. Now classify real sequencing data: Illumina MiSeq reads of the 16S V4 region from mouse feces, from the mothur MiSeq SOP (Kozich et al., 2013).

5. Is it 16S at all? Significance and negative controls

A search always returns some best hit, even for a query that is not a 16S sequence. Use the empirical p-values from the second half of the lecture to tell real hits from noise.

def fetch_ncbi(accession: str) -> skbio.DNA:
    response = requests.get('https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi',
                            params={'db': 'nuccore', 'id': accession, 'rettype': 'fasta'})
    return skbio.DNA.read(io.StringIO(response.text), lowercase=True)

controls = {
    'E. coli 16S rRNA (positive)':     'NR_024570.1',

More options

  • Swap the database. Replace the outdated Greengenes 13_8 with SILVA or the NCBI 16S RefSeq set. Do the Exercise 4 compositions change?
  • Compare with the real tool. Install BLAST+ (conda install -c bioconda blast), run makeblastdb on your reference subset and blastn on your queries. Do the top hits agree with yours, and how much faster is BLAST?
